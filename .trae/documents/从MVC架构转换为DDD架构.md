# 从MVC架构转换为DDD架构

## 1. 架构设计

### 1.1 领域划分
- **用户领域**：User
- **好友领域**：Friend
- **群组领域**：Group, GroupMember
- **消息领域**：Message
- **通信领域**：WebSocket相关

### 1.2 DDD分层结构
```
com.linkchat
├── application/          # 应用层
│   ├── command/          # 命令
│   ├── query/            # 查询
│   ├── service/          # 应用服务
│   └── dto/              # 数据传输对象
├── domain/               # 领域层
│   ├── user/             # 用户子域
│   │   ├── entity/       # 实体
│   │   ├── value/        # 值对象
│   │   ├── service/      # 领域服务
│   │   └── repository/   # 仓储接口
│   ├── friend/           # 好友子域
│   ├── group/            # 群组子域
│   └── message/          # 消息子域
├── infrastructure/       # 基础设施层
│   ├── persistence/      # 持久化实现
│   ├── netty/            # Netty通信
│   └── security/         # 安全相关
└── interfaces/           # 接口层
    ├── rest/             # REST API
    └── websocket/        # WebSocket接口
```

## 2. 转换步骤

### 2.1 第一步：重构领域层
- 将当前Entity转换为领域实体
- 识别聚合根：User, Group, Message
- 设计值对象：如UserId, GroupId, MessageContent等
- 实现领域服务
- 定义仓储接口

### 2.2 第二步：构建应用层
- 创建应用服务，协调领域对象
- 设计命令和查询模型
- 实现DTO转换

### 2.3 第三步：重构基础设施层
- 实现仓储接口
- 调整Netty通信模块
- 整合现有技术栈

### 2.4 第四步：重构接口层
- 将Controller迁移到interfaces/rest
- 调整WebSocket相关代码

### 2.5 第五步：测试与验证
- 确保所有功能正常工作
- 运行现有测试用例
- 补充领域层测试

## 3. 核心转换要点

### 3.1 实体转换
- 将`@Data`实体改为带有行为的领域实体
- 实现实体的业务规则
- 保护实体的不变量

### 3.2 仓储模式
- 从直接使用Mapper改为通过仓储接口访问数据
- 仓储接口定义在领域层，实现在基础设施层

### 3.3 服务分层
- 区分领域服务和应用服务
- 领域服务处理核心业务逻辑
- 应用服务处理流程协调

### 3.4 值对象设计
- 提取如用户名、邮箱、消息内容等值对象
- 实现值对象的相等性比较

## 4. 技术实现

### 4.1 依赖管理
- 保持现有技术栈（Spring Boot, MyBatis, Netty）
- 增加必要的DDD支持库

### 4.2 包结构调整
- 按照DDD分层重新组织代码
- 逐步迁移，确保系统可运行

### 4.3 测试策略
- 单元测试：测试领域对象
- 集成测试：测试应用服务和仓储
- 端到端测试：测试完整业务流程

## 5. 转换顺序

1. **用户领域**：首先转换用户相关代码，建立基础架构
2. **好友领域**：基于用户领域扩展好友功能
3. **群组领域**：实现群组和群成员管理
4. **消息领域**：实现消息发送和存储
5. **通信领域**：调整WebSocket通信，集成到DDD架构

通过以上步骤，将系统从传统MVC架构转换为DDD架构，提高系统的可维护性、扩展性和业务表达能力。
