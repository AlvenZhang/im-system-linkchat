# 恢复缺失的领域实体类计划

## 1. 问题分析

当前项目中，`domain` 目录下只有用户子域的实体类，好友、群组和消息相关的实体类缺失。根据DDD架构原则，每个子域都应该有自己的实体类，用于表达核心业务概念和业务逻辑。

## 2. 解决方案

为每个子域创建对应的领域实体类和数据库实体类，包括：

### 2.1 好友子域
- **领域实体**：`domain/friend/entity/Friend.java`
- **数据库实体**：`infrastructure/persistence/entity/Friend.java`

### 2.2 群组子域
- **领域实体**：`domain/group/entity/Group.java`
- **领域实体**：`domain/group/entity/GroupMember.java`
- **数据库实体**：`infrastructure/persistence/entity/Group.java`
- **数据库实体**：`infrastructure/persistence/entity/GroupMember.java`

### 2.3 消息子域
- **领域实体**：`domain/message/entity/Message.java`
- **数据库实体**：`infrastructure/persistence/entity/Message.java`

## 3. 实现步骤

### 3.1 第一步：创建好友子域实体类

- 创建 `domain/friend/entity/Friend.java`
- 创建 `infrastructure/persistence/entity/Friend.java`
- 参照 `init.sql` 中 `friend` 表的结构定义属性

### 3.2 第二步：创建群组子域实体类

- 创建 `domain/group/entity/Group.java`
- 创建 `domain/group/entity/GroupMember.java`
- 创建 `infrastructure/persistence/entity/Group.java`
- 创建 `infrastructure/persistence/entity/GroupMember.java`
- 参照 `init.sql` 中 `group` 和 `group_member` 表的结构定义属性

### 3.3 第三步：创建消息子域实体类

- 创建 `domain/message/entity/Message.java`
- 创建 `infrastructure/persistence/entity/Message.java`
- 参照 `init.sql` 中 `message` 表的结构定义属性

### 3.4 第四步：更新Mapper接口中的实体引用

- 更新所有Mapper接口中的实体导入语句，确保引用的是正确的数据库实体类

## 4. 预期结果

通过以上步骤，每个子域都将拥有自己的领域实体类和数据库实体类，项目结构将完全符合DDD架构原则，便于后续的开发和维护。
