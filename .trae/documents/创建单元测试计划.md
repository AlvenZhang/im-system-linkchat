# 创建单元测试计划

## 测试框架和工具
- 使用JUnit 5作为测试框架
- 使用Mockito进行依赖模拟
- 保持与现有测试风格一致

## 测试范围

### 1. 领域层测试

#### 值对象测试
- **EmailTest**：测试邮箱格式验证、相等性比较
- **UsernameTest**：测试用户名格式验证、相等性比较
- **UserIdTest**：测试用户ID的创建和验证

#### 领域服务测试
- **UserDomainServiceTest**：
  - 测试用户名可用性验证
  - 测试邮箱可用性验证
  - 测试用户创建成功场景
  - 测试用户名已存在异常场景
  - 测试邮箱已存在异常场景

### 2. 应用层测试

#### 应用服务测试
- **UserApplicationServiceTest**：
  - 测试用户注册成功场景
  - 测试根据ID查询用户
  - 测试根据用户名查询用户
  - 测试更新用户信息
  - 测试更新不存在用户异常场景

### 3. 现有测试更新

#### 更新LinkChatApplicationTests.java
- 更新为使用新的DDD结构
- 移除对旧MVC组件的引用
- 添加新的集成测试示例

### 4. 测试目录结构

遵循项目的包结构，在`src/test/java`下创建对应的测试目录：
```
src/test/java/com/linkchat/
├── application/
│   └── service/
│       └── UserApplicationServiceTest.java
├── domain/
│   └── user/
│       ├── service/
│       │   └── UserDomainServiceTest.java
│       └── value/
│           ├── EmailTest.java
│           ├── UsernameTest.java
│           └── UserIdTest.java
└── LinkChatApplicationTests.java (更新)
```

## 测试编写要点

1. **单元测试独立性**：每个测试方法只测试一个功能点
2. **使用模拟对象**：对外部依赖（如Repository）使用Mockito模拟
3. **测试边界条件**：包括正常场景、异常场景、边界值
4. **断言清晰**：使用JUnit 5的断言API，确保测试结果明确
5. **测试命名规范**：使用`should_ExpectedBehavior_When_StateUnderTest`格式

## 预期结果

- 所有单元测试通过
- 测试覆盖率达到关键业务逻辑的80%以上
- 测试代码结构清晰，易于维护和扩展
- 能够验证DDD架构下的核心业务逻辑正确性
